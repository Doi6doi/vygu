# Contributing to vygu

Contributions are welcome. 

## Reporting bugs

Please use GitHub Issues to report bugs. 
Please include sufficient details to be able
to reproduce the error.

## Pull requests

As things are still about to take form, and many source files
are getting changed, rather just post an issue with your idea.
You can link to your new code, I will read it through.

## Coding style

Somewhat nitpicky. Indentation goes with 3 spaces, methods,
and fields are camel case, constants are all caps. Classes, 
fields, constants, and non-override methods should have a one 
line natural language comments before them. 
If it is a (wiki) documented function, it should be
a /// or /** doc-comment with optional \param and \return, 
beacause documentation is generated by vydox.

## Platform-specific code

Platform-specific implementations should all go to engine classes
(like Gtk4 and WinApi)
